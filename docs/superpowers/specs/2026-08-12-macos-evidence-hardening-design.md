# macOS Evidence Hardening Design

Date: 2026-08-12
Status: approved for implementation

## Objective

Close the acceptance-tool weaknesses found during the Windows parity review
using work that can be fully implemented and verified on macOS. The stage makes
performance samples continuous and auditable, requires six genuinely distinct
runs, validates binary identities strictly, and then reruns the shared macOS
H.264, GUI, and screen-call regression surface affected by the Windows merge.

This stage does not modify or claim native Windows Media Foundation behavior.

## Selected approach

Add strict validation to `scripts/run_windows_screen_acceptance.py` rather than
creating another aggregator. The existing JSONL remains the source of truth,
while validation rejects incomplete sample cadence, duplicate artifacts,
malformed SHA-256 identities, mismatched run metadata, and reused run
identities before statistics are computed.

Alternative approaches were rejected:

- Documentation-only warnings would not prevent invalid evidence from passing.
- A second comparison script would duplicate rules and permit two conflicting
  acceptance paths.
- Editing Media Foundation code on macOS would create unverified Windows-native
  changes and is outside this stage.

## Evidence contract

### Continuous process samples

For each host and viewer measurement window:

- `elapsed_seconds` is an integer, strictly increasing, and unique;
- the first sample equals the requested window start;
- the last sample equals the requested window end;
- adjacent samples differ by exactly one second;
- the sample count equals `end - start + 1`;
- CPU is finite and nonnegative;
- RSS is a positive integer.

Any violation raises a stable `AcceptanceError` category before percentile or
mean calculation.

### Independent runs

Comparison accepts exactly three baseline and three hardware artifacts. All six
resolved artifact paths must be distinct. Each JSONL `run` record gains a
non-sensitive `run_id` generated by the runner, and all six run IDs must be
distinct. Reusing one artifact or copying the same run under another filename
fails closed.

### Binary identity

`demo_sha256` must be exactly 64 lowercase hexadecimal characters. All six runs
must use the same digest. The digest proves executable identity only; it does
not prove Git identity or platform behavior.

### Compatibility

The schema remains `windows-screen-comparison-v1`. Existing complete artifacts
without `run_id` remain readable for single-run diagnostics, but cannot satisfy
the frozen three-versus-three comparison. New runs always emit `run_id`.

## macOS regression boundary

After the portable tooling is green, verify on macOS:

- focused Python acceptance contracts;
- workflow and ShareMe skill validation;
- `call-dev` configuration and full CTest;
- `movie-call-dev` configuration and full CTest when existing dependencies are
  available;
- repeated `signaled_peer` lifecycle;
- a native standard VideoToolbox screen-call smoke with H.264 active;
- GUI lifecycle smoke when the configured app and display permissions permit;
- Go signaling tests, race tests, and vet;
- forbidden-header scan and `git diff --check`.

macOS success proves only the macOS/shared regression boundary. The hardened
comparison logic requires a later Windows rerun before replacing the historical
Windows performance evidence.

## Failure handling

- Test-first RED evidence is required for every validation rule.
- Partial or malformed artifacts never produce accepted statistics.
- Generated JSONL, build output, logs, screenshots, and caches remain ignored.
- The repository-external libwebrtc checkout and cache remain read-only.
- If a native macOS dependency or permission is unavailable, record that check
  as environment-dependent and continue with every independent verifiable gate.

## Delivery outcome

The stage ends as one of:

- `verified-macos-evidence-hardening`: all portable tooling and available
  macOS shared regressions pass;
- `partial-macos-evidence-hardening`: tooling passes but a named native macOS
  regression is environment-dependent;
- `blocked-on-evidence-contract`: the hardened contract or affected portable
  tests cannot pass.

Windows Media Foundation hardware decoder selection, per-profile native codec
probing, two-device acceptance, cursor composition, display selection, 4K, and
thermal observation remain later Windows-native work.
